API - Newman

Backend API test cases

8 requests executed against /api/health and /api/generate-plan, covering happy paths, goal-specific logic, and negative input validation. 32 assertions in total.

IDTest CasePriorityWhatWhyHowExpected
API-01 Health check endpoint is reachableSource: backend/postman_collection.json - Health Check High Verify the backend reports a healthy status. Liveness gate - every other API case depends on the service being up. Catches startup failures instantly.
  1. Start the backend on port 4000.
  2. Send GET /api/health.
  3. Inspect status code, JSON body and response time.
 200 OK; body contains status "OK" and service "Gymini API"; response time below 1000 ms.
API-02 Generate plan with a valid requestSource: backend/postman_collection.json - Generate Plan - Valid Request High Verify the core endpoint returns a complete, well-formed plan for valid input. Happy path of the main business feature - a regression here breaks the whole product.
  1. POST /api/generate-plan with age 30, male, 178 cm, 82 kg, build-muscle, intermediate, 4 days, 60 min, gym.
  2. Validate the response structure and payload fields.
 200; mode "mock-ai"; headline present; weeklyPlan is an array of 4 days; every day has at least one exercise; progression and safety fields present; under 2000 ms.
API-03 Strength goal drives rep scheme and restSource: backend/postman_collection.json - Generate Plan - Strength Goal Medium Verify goal=strength produces low-rep prescriptions and longer rest. The domain logic must translate user goals into the correct training parameters.
  1. POST /api/generate-plan with goal=strength, advanced, 4 days.
  2. Assert headline, first exercise prescription and rest text.
 200; headline includes "strength"; prescription includes "4-6"; rest includes "2-3 minutes".
API-04 Fat-loss goal drives rep scheme and finisherSource: backend/postman_collection.json - Generate Plan - Fat Loss Goal Medium Verify goal=fat-loss produces higher-rep work and a cardio finisher. Ensures the goal-specific logic differs correctly from strength and muscle-building paths.
  1. POST /api/generate-plan with goal=fat-loss, beginner, 3 days.
  2. Assert headline, rep scheme and finisher.
 200; headline includes "fat loss"; prescription includes "10-15"; finisher includes "incline walk".
API-05 Bodyweight equipment onlySource: backend/postman_collection.json - Generate Plan - Bodyweight Equipment Medium Verify equipment=bodyweight never returns exercises that need gym equipment. Guards against recommending equipment the user does not have - a core correctness rule.
  1. POST /api/generate-plan with equipment=bodyweight, build-muscle, 3 days.
  2. Collect every exercise name across all days and compare to the bodyweight-safe list.
 200; every exercise is one of Push-ups, Goblet squats, Dumbbell rows, Romanian deadlifts, Plank, Walking lunges.
API-06 Missing required fields rejectedSource: backend/postman_collection.json - Generate Plan - Missing Required Fields High Verify a partial payload is rejected with a clear, structured error. Input validation - malformed requests must not crash the API or produce a broken plan.
  1. POST /api/generate-plan with only {"age":"30"}.
  2. Assert status, message text and the missing-fields array.
 400; message includes "Missing"; response lists a non-empty "missing" array.
API-07 Empty body lists all required fieldsSource: backend/postman_collection.json - Generate Plan - Empty Body High Verify an empty payload names every required field. Defensive coding - the API must tell the caller exactly what is missing, not just fail.
  1. POST /api/generate-plan with {}.
  2. Assert the complete list of required fields.
 400; missing contains age, height, weight, goal, experience, daysPerWeek, equipment.
API-08 Day count changes plan length and splitSource: backend/postman_collection.json - Generate Plan - Different Day Counts Medium Verify daysPerWeek=2 returns a 2-day full body plan. Plan length must respect user preference while still producing a sensible split.
  1. POST /api/generate-plan with daysPerWeek=2, general-fitness, beginner.
  2. Assert day count and first-day split name.
 200; weeklyPlan has 2 days; first day focus includes "Full Body".
